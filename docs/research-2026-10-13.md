# Nano Banana 2.1 詳細調査

調査日：2026-10-13（日本時間）

## 結論

Nano Banana 2.1は2026-10-06に一般提供されたGoogleの画像生成・編集モデルです。正式IDは `gemini-nano-banana-2.1`。ニュースの中心にあるマスク・手描き指示による編集能力は公式に確認できます。ただし「選択範囲外を完全保持」「決定論的な制御」という部分は、公開APIの保証として確認できません。[リリースノート](https://ai.google.dev/gemini-api/docs/changelog)、[製品ページ](https://deepmind.google/models/gemini-image/flash/)

簡易Photoshopの開発には有望です。生成と意味に基づく編集をAIに担当させ、選択範囲、レイヤー、文字、画像合成、Undo/Redoをアプリ側で実装すれば、使いやすさと編集の確実性を両立できます。これは調査から導く設計提案であり、実機での品質検証結果ではありません。

## 1. ニュースの検証

| 引用された主張 | 判定 | 根拠・解釈 |
|---|---|---|
| Nano Bananaが2.1に更新された | 確認済み | Googleの2026-10-06リリースノートに一般提供が掲載されている |
| マスクを使う編集に対応する | 能力として確認済み | 製品ページにMask-based editing、モデルカードにMask/Ink-Based Editingの評価がある |
| 専用の画素マスクをAPI引数として渡せる | 公開仕様では未確認 | 現行ガイドは画像と自然言語によるsemantic masking。Interactions、generateContentのリファレンスにも専用mask項目を確認できない |
| 手描きスケッチや注釈による指示に対応する | 確認済み | 現行公式ガイドにスケッチ入力の例がある |
| スケッチ対応は2.1で初めて搭載された | 不正確 | Googleは2025-10-02にもスケッチを写実画像にする例を紹介している |
| 選択範囲外の要素を完全に保持する | 保証は確認できない | モデルカードは指示への部分的な追従と描画線の残存を既知の限界に挙げる |
| 編集を決定論的に制御できる | 根拠不足 | 対象の理解・生成は確率的。seedが使える一般モデルにも完全な決定性の保証はない |

根拠：[画像生成ガイド](https://ai.google.dev/gemini-api/docs/image-generation)、[Interactions APIリファレンス](https://ai.google.dev/api/interactions-api)、[generateContentリファレンス](https://ai.google.dev/api/generate-content)、[2025年のGoogle記事](https://blog.google/products-and-platforms/products/gemini/nano-banana-tips/)、[モデルカード](https://deepmind.google/models/model-cards/nano-banana-2-1/)

「マスク編集能力」と「編集してよい画素を強制的に制限するAPI」は別です。前者は塗りや線の意図を理解して編集する能力、後者は選択範囲外の変更をシステムとして禁止する機構です。調査した公開資料で確認できるのは前者です。

Interactionsの汎用設定にはseedが存在しますが、そのことだけでは2.1での利用可否を証明できません。Google Cloudの2.1個別仕様ではseed、temperature、topP、topK、logprobsを非対応と明記しています。Developer APIで同じ結果になるとの実測はしていません。アプリに「同じseedなら同じ画像」機能を約束する根拠にはできません。[Cloud個別仕様](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/nano-banana-2-1)、[一般的な生成パラメーターの説明](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/prompts/adjust-parameter-values)

## 2. モデルとAPIの仕様

AI Studioで作るアプリの基準はGemini Developer APIのモデル個別ページに置きます。Cloud固有の制限や料金を混ぜません。

| 項目 | 2.1の確認内容 |
|---|---|
| モデルID | `gemini-nano-banana-2.1`、Stable |
| 入力／出力 | 入力はテキスト・画像・動画・PDF。出力は画像・テキスト |
| 解像度 | 1K・2K・4K、既定1K。512pxは2.1の対応一覧にない |
| 画像参照 | 合計最大14枚。人物の一貫性は最大4人、物体は最大10点と記載されている |
| 思考設定 | minimal / medium / high、既定medium |
| 検索 | Web検索・画像検索によるグラウンディング |
| コンテキスト | 入力131,072、出力32,768トークン |
| 非同期の大量処理 | Batch対応 |
| 非対応 | 音声生成、Live API、function calling、structured output、code execution、URL context、File Search、Maps、Developer APIのcachingなど |

根拠：[モデル個別仕様](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1)

参照画像の14枚は、人物14人の同一性を保証する意味ではありません。また、編集用に元画像・注釈画像を2枚送る場合、その分も合計枚数に含める設計が必要です。

現行ガイドのアスペクト比は `1:1, 1:4, 1:8, 2:3, 3:2, 3:4, 4:1, 4:3, 4:5, 5:4, 8:1, 9:16, 16:9, 21:9`。1K等の名称は解像度区分で、常に長辺が1024・2048・4096になる意味ではありません。例えばガイドの4K・8:1は12288×1536です。取り込んだ写真が任意サイズの場合、AI出力との位置合わせが必要になります。[画像生成ガイド](https://ai.google.dev/gemini-api/docs/image-generation)

動画入力はサムネイルやポスターを作るための参照に使えます。動画を出力するモデルではありません。PDFも資料を参照するための入力であり、編集可能なPDFやPSDを出力する機能とは別です。

## 3. 2からの改善はどこまで裏づけられるか

Googleは画質、プロンプト追従、会話を重ねた人物の一貫性、文字の描画改善を挙げています。旧2の `gemini-3.1-flash-image` は非推奨化され、2.1への移行が案内されています。調査時点のリリースノートでは旧2の終了日は未発表です。[リリースノート](https://ai.google.dev/gemini-api/docs/changelog)

モデルカードには人間の比較評価が掲載されています。次は代表的な項目の抜粋です。

| 評価（Elo） | 2.1・思考あり | 2・思考あり |
|---|---:|---:|
| 全体のText-to-Image | 1050 ±14 | 990 ±7 |
| Mask/Ink-Based Editing | 1049 ±15 | 965 ±12 |
| 複数人物の一貫性 | 1106 ±14 | 978 ±10 |

この評価はGoogleが定義した比較試験のスコアです。成功率、画素の保存率、性能が何％改善したかを直接表すものではありません。ベンチマークの「思考なし」区分も、Developer APIでthinkingを完全に無効にできることを意味しません。現行ガイドでは思考の無効化はできず、minimalを選べます。[モデルカード](https://deepmind.google/models/model-cards/nano-banana-2-1/)、[画像生成ガイド](https://ai.google.dev/gemini-api/docs/image-generation)

## 4. 苦手なことと実用上の境界

モデルカードは、小さな文字・長い文章、人物の完全な同一性、マスク指示への追従、注釈線の消去、姿勢変更、左右の指示、事実・3D理解、遅延やタイムアウトに限界があると記載しています。用途に応じた検証が必要です。[モデルカード](https://deepmind.google/models/model-cards/nano-banana-2-1/)

商品ラベルの細かな文字、値段、固有名詞を確実に変更したい場合は、AIに背景や材質を作らせ、文字はアプリのテキストレイヤーで重ねる方が制御しやすくなります。衣装の変更はAI向きですが、体形・輪郭・ポーズも常に完全保持されるとは扱いません。

透明背景の正確なアルファ出力、PSD互換の編集可能レイヤー、ICC/CMYKによる印刷品質、写真からの自動選択・精密な切り抜きは、2.1の公開仕様からは保証できません。レイヤーや透明化はアプリ側の機能として設計します。生成画像にはSynthIDが付与されます。[画像生成ガイド](https://ai.google.dev/gemini-api/docs/image-generation)

## 5. 料金

以下はStandardの画像出力部分、米ドル、2026-10-13確認。税、為替、入力、テキスト・思考、検索、アプリのホスティングは別です。

| 解像度 | 2.1 Standard／枚 | 2 Standard／枚 | 2.1 Batch／枚 |
|---|---:|---:|---:|
| 1K | $0.0336 | 約$0.067 | $0.0168 |
| 2K | $0.0504 | 約$0.101 | $0.0252 |
| 4K | 約$0.1134 | 約$0.151 | $0.0567 |

4Kは公式表の丸め表示が$0.113、同ページの3,780トークン×$30/100万トークンで計算すると$0.1134です。1K・2Kの画像出力費用は旧2の約半額ですが、4Kは約25％減です。入力は$1.50/100万トークン、テキスト・思考出力は$7.50/100万トークン。旧2比でそれぞれ3倍、2.5倍なので、総額が常に半額になるわけではありません。[公式料金表](https://ai.google.dev/gemini-api/docs/pricing)

画像出力だけなら、1Kを100枚で$3.36、2Kを100枚で$5.04、4Kを100枚で$11.34。これは計算上の目安で、実測した請求額ではありません。

概算式：

`総額 = 入力tokens × 1.50/1,000,000 + テキスト・思考出力tokens × 7.50/1,000,000 + 画像出力tokens × 30/1,000,000 + 検索料金`

検索の無料枠はGemini 3以降のモデル間で月5,000検索リクエストを共有し、その後$14/1,000。1回の生成要求が複数の検索を行うことがあります。検索で取得されたコンテキストは入力トークンとして課金されません。2.1のAPI料金表に無料利用枠はありません。AI Studioを開けることと、作ったアプリの画像APIを無料で運用できることは分けて考えます。[公式料金表](https://ai.google.dev/gemini-api/docs/pricing)

開発時は1K・1候補・検索OFFを既定にし、2K/4K、候補追加、検索を明示的に選ぶ設計が適しています。Batchは待てる一括処理用で、対話的な編集の即時応答を約束しません。

## 7. AI Studioで作る場合の構成

AI Studio BuildはReactを基本とするフロントエンドとNode.jsのサーバーを含むアプリを作れます。APIキーはサーバー側のSecretとして扱われます。GitHubとの同期・取り込み、ZIPでの持ち出し、Cloud Runへのデプロイも用意されています。[AI Studio Build公式説明](https://ai.google.dev/gemini-api/docs/aistudio-build-mode)

推奨構成は「React編集画面 → Node API → Gemini Developer API」です。ローカル画像編集・合成・履歴はブラウザ、APIキー・要求検証・生成呼び出しはサーバーが担当します。

現行GoogleガイドはInteractions APIを推奨し、画像生成例もそれを使います。既存generateContentも引き続きサポートされています。新規アプリではAPIアダプターを設け、Interactionsから始める方針とします。SDK・AI Studioの実環境で互換性に問題があれば、公式generateContent経路への切替を限定して検証します。[Interactions概要](https://ai.google.dev/gemini-api/docs/interactions-overview)、[画像生成ガイド](https://ai.google.dev/gemini-api/docs/image-generation)

Interactionsには `previous_interaction_id` による会話の継続があります。ただしsystem instruction、tools、generation configは次の要求で再指定する必要があります。既定のstore=trueはサーバーに履歴を保存し、有料枠で55日、無料枠で1日と記載されています。初期版はstore=falseで必要な文脈を明示送信し、画像・プロジェクトはIndexedDBとダウンロードで保存する案です。これにより無制限に古い画像を再送する設計を避けます。store=falseを「Google側であらゆるデータが一切保存されない」と説明してはいけません。[Interactions概要](https://ai.google.dev/gemini-api/docs/interactions-overview)

共有・公開後も利用者の生成は作成者のAPIキー・利用枠に計上されます。公開版には認証、サーバー側の回数制限と予算管理が必要です。今回の開発は個人用の非公開プレビューから開始する設計です。[AI Studio Build公式説明](https://ai.google.dev/gemini-api/docs/aistudio-build-mode)

## 8. 実装前に試すべきこと

1. モデルIDで1K生成できるか、設定・レスポンス・usageの形式を確認する。
2. 元画像のみ＋文章、元画像＋注釈画像＋文章を同じ素材で比較する。注釈画像は通常の画像入力として渡す。
3. 小物削除、衣装変更、背景変更、商品ラベル、スケッチ仕上げを試す。
4. 元画像とAI出力の寸法・構図のズレを確認し、マスク合成後の選択範囲外RGBA一致を検証する。
5. 注釈線が残る、人物が変わる、文字が誤る、拒否されるケースを保存する。
6. 2K/4Kの料金・待ち時間、タイムアウト時の取得・再試行の扱いを確認する。

今の結果は公式資料の調査であり、これらの実験は未実施です。公開APIの専用mask項目と決定性についてはAstraの独立検証でも同じ結論でした。画像生成APIは呼び出していません。
