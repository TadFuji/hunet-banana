# Banana Studio 現行設計

2026-10-13。AI Studio Build案からReact / TypeScriptの独自ウェブアプリへ変更した。利用者自身のGemini APIキーでGoogleへ直接接続する。対象はPhotoshopに慣れた人。旧案は [検討履歴](app-design-ai-studio-archive.md) に保存した。

## 画面と編集

上部にファイル・編集・画像・レイヤー・選択範囲・表示メニュー、左にツール、中央にキャンバス、右にAI・レイヤー・履歴パネル、下部に履歴とステータスを置く。システムフォントと同梱アイコンのみを使う。

Projectは文書サイズと画像レイヤーの配列を持つ。下から上へ描画し、表示状態・不透明度・描画モード（`normal` / `multiply` / `screen` / `overlay` / `darken` / `lighten` / `color-dodge` / `color-burn` / `hard-light` / `soft-light` / `difference` / `exclusion` の12種）を適用する。表示倍率（1〜800%）は画面上のCanvas要素の大きさだけを変え、文書の画素は変えない。文書サイズが変わるたび（画像を開く、生成結果やBatch結果の採用、読込、拡張など）に、編集領域へ全体が収まる倍率（最大100%）へ自動で合わせる。⌘/Ctrl＋ホイールとピンチはポインター位置を中心に拡大縮小する。移動はPNGを描き直さず、レイヤーの整数オフセット`x`・`y`（省略時0、保存時は絶対値16,384以下）だけを更新するため、キャンバス外へ出た画素も保持される。キャンバス拡張時はオフセットを反映した画像に描き直し、オフセットを0に戻す。新しい文書範囲にレイヤーの全画素が収まらない場合は拡張を中止し、サイズを大きくするかレイヤーを内側へ戻すよう案内する。文字もPNGレイヤーにする。選択とスケッチは同じサイズの別Canvasで保持する。最大24ステップの履歴には文書・選択・スケッチを含める。

保存は固定スキーマだけを含み、キー・会話・参照素材・履歴を含めない。独自JSON、IndexedDBの1件保存、PNG出力、および標準Web APIのみで実装したPhotoshop PSD（`.psd`、RGB 8bit・非圧縮およびPackBits RLE読込・Unicodeレイヤー名 `luni`・オフセット・不透明度・表示状態・12種の描画モード・合成プレビュー画像）の読み書きを実装する。選択・スケッチは保存していないため再読込で消える。

## 生成と採用

generateContentを使いモデルIDを固定する。1K/2K/4K、14比率、3段階の思考、Web/画像検索を選択できる。全体編集では可視レイヤーの合成画像と指示を送る。スケッチでは元画像と手描き線を重ねた指示画像を送る。画像・動画・PDFは参照素材としてインライン添付（各14MiB・合計19MBまで）できるほか、APIキー接続時はGoogle Files API（最大200MB、`POST /upload/v1beta/files?uploadType=multipart`）へアップロードして `fileData`（`fileUri`）として参照でき、状態更新（`GET /v1beta/files/{id}`）と削除（`DELETE /v1beta/files/{id}`）を行える。

候補を表示し、利用者が採用するまで文書を変更しない。採用すると結果レイヤーを追加し、既存レイヤーを非表示にする。Undoで以前の文書へ戻れる。生成中に別の編集があった場合は、採用すると現在の編集を置き換えることを知らせる。

採用した生成のuser/modelペアとthought signatureをタブ内に保持し、次の編集へ引き継ぐ。最大3ペアを保持し、送信時に14画像・19MBを超える場合は古いペアから除く。新規文書、画像・プロジェクトの読込、Batch画像採用では会話をリセットする。

## 部分編集

専用mask引数があるとの前提を置かない。元画像と選択箇所を着色した注釈画像を通常の画像入力として送る。文書が対応比率と合わない場合は、近い比率の作業用キャンバスに余白を足す。

候補の比率を検証し、余白を除き元のサイズへ戻す。その後、Canvas上の元画像・候補・選択のRGBAから合成する。選択alphaが0なら元をコピー、255なら候補をコピーする。中間alphaはpremultiplied alphaを考慮して混ぜる。モデルが候補の周辺を描き直しても、採用結果の未選択部分を保てる。

対象はアプリ内に描画した元画像と合成結果の画素。元JPEG等のファイルバイト、EXIF、ICCプロファイル、完全透明画素の不可視RGBを保持する保証ではない。生成内容の指示追従・人物の同一性・線の消去はモデルに依存する。

## BYOKと配信

静的サーバーはキーや素材を受け取らない。入力欄を空にしてキーを専用Workerの一時メモリへ渡す。固定Google APIにだけヘッダーで付ける。画面へ返す前にキー文字列を伏字にし、生APIエラーを表示しない。

文書のCSPはネットワークを禁止し、WorkerのCSPはGoogleだけを許可する。本番サーバーが個別にヘッダーを付ける。リダイレクト禁止、Cookie未送信、同梱コード、検索HTMLのsandboxを組み合わせる。解除・ページ離脱・15分無操作でWorkerを終了する。開発サーバーではキー接続を無効にする。詳細は [security.md](security.md)。

## Batchと制限

Batchは最大20件の指示による一括作成、状態取得、中止要求、結果採用を実装する。新規生成だけでなく、「Batchでキャンバスの画像を編集」を有効にした全体編集・部分編集・スケッチ指示、参照素材（インライン添付およびFiles API `fileData`）、Web検索・画像検索設定の引き継ぎと出典・検索提案の表示に対応する。部分編集モードでBatch結果を採用する際も、通常生成と同様にアプリの `applyMask` で未選択画素を元画像からコピーして合成する。最後のIDと状態だけを保存する。中止は既発生の料金の取り消しを保証しない。

インライン添付は各ファイル14MiB・送信合計19MB、Files APIアップロードは各ファイル200MBまで、受信80MB、文書3,200万画素・各辺16,384px・40レイヤー。新規作成・拡張は各辺8,192px。大量の4K Batchは受信制限に達する場合がある。Photoshopの調整レイヤー・スマートオブジェクト・CMYK、Interactions API、複数候補の同時比較は未実装。Webで主要な生成・編集能力を使えるため、現段階ではMac専用アプリへ移す必要はない。
