## 結論

Astraによるセキュリティと編集操作の別担当レビュー、Solによる修正、本体による回帰検証、Astraの再レビューを実施しました。確認範囲で未解消のP0〜P2指摘はありません。最終版は単体13件・ブラウザ22件が成功し、依存関係監査の検出は0件です。

最初のレビューでP2を6件、P3を2件確認し修正しました。修正後の再レビューで見つかった会話履歴・選択履歴・Batch作成結果の3つの整合性問題も、追加修正と回帰テストで対応しています。レビュー結果はローカル実装の確認であり、実Google接続や一般公開の実証とは区別します。

## 担当と確認方法

- Astra・セキュリティ担当：Worker内のキー、固定送信先、CSP、エラー・検索HTML・保存境界、入力検証。ソース読解と隔離Chromeで不正画像の読込を再現し、修正後に再レビュー。
- Astra・編集担当：非同期編集、候補採用、レイヤー、履歴、保存、Batch。隔離Chromeで複数の操作を再現し、修正後のソース・テストを再レビュー。
- Sol・実装担当：App.tsxの修正とビルド。本体がAPI境界・画像検証・回帰テスト・説明書を統合し、最終ビルドと全テストを実行。

利用者の既存ブラウザ・保存作品・実APIキーは使用していません。ブラウザ試験は別コンテキスト、ダミーキー、ローカルで置き換えたAPI応答で行いました。有料API生成・デプロイ・Googleアカウント変更は実行していません。

## 修正した指摘

| 優先度 | 発生条件と以前の挙動 | 修正後 |
|---|---|---|
| P2 | 不正なPNGや実寸超過の隠しレイヤーを含むプロジェクトを、画像検証より先に適用 | 全レイヤーのデコード・実寸・合計画素を検証してから適用。拒否時は現在の文書を保持。IndexedDB復元も同様 |
| P2 | Batch Aの更新中にBを読み込み、遅いAの応答で内部の対象がAへ戻る | 要求の世代と対象IDを照合。Bが維持され、中止もBを対象にする |
| P2 | 40レイヤーで候補を採用すると、文書への追加に失敗しても候補を閉じ成功表示 | 更新の成否を確認してから候補を閉じる。上限拒否時は候補・文書を保持 |
| P2 | 大きさの異なるAI結果の採用後、元レイヤーを移動・拡張すると元の実寸へ縮む | 移動のプレビュー・確定と拡張で、文書の表示寸法を明示して描画 |
| P2 | 画像処理・読込を待つ間に文書を編集すると、古い処理結果で変更が上書きされる | 処理開始時の文書とrevisionを保持し、検証後にも一致を確認。不一致時は現在の編集を維持 |
| P2 | 保存中に編集しても、古い保存の完了で現在の文書が保存済みになる | 保存対象のrevisionが現在と一致するときだけ保存済み。新しい編集は未保存と案内 |
| P3 | ズームの説明が修飾キーなしで、実装と不一致 | README・PDFを⌘/Ctrl付きの操作に修正 |
| P3 | 新規生成の案内が「参照画像を使わない」で、実際の素材送信と不一致 | 文章と参照素材からの新規生成と明記 |

再レビューでは、選択描画や名称変更で採用済みのAI会話を消さないよう、リセットを画像・構成が変わる場合に限定しました。下部・右側の任意履歴復元を共通処理に統一し、選択・スケッチの参照とAI会話も同期します。Batch作成中は既存IDの読込を止め、作成結果のジョブIDを表示・保存する機会を失わないようにしました。

文書画素数×層数と、埋込画像の実寸合計をそれぞれ128,000,000画素までに制限します。画像の追加・候補採用等でも実寸合計を検証し、保存した文書が次回の復元で拒否される不整合を防ぎます。拡張は全レイヤー分を割り当てる前に上限を検査します。

API応答の不正なBatch状態・配列・生成partを安全に拒否し、任意の検索メタデータや使用量の異常値を処理する境界検証も追加しました。

## API仕様・料金・残る確認範囲

現在のアプリが使うモデルの生成経路・画像設定・思考署名・検索設定を[Googleの画像生成ガイド](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)と照合し、料金表も[公式料金ページ](https://ai.google.dev/gemini-api/docs/pricing)で再確認しました。取扱説明書の料金・キー作成・課金手順は2026年10月13日確認の資料に基づきます。

APIキーがURL・本文・DOM・保存領域・プロジェクト・コンソールに残らないこと、Googleの固定先のヘッダーでのみ送られること、応答中の伏字、Workerと文書それぞれのCSP、検索HTMLの隔離、別オリジンへのリダイレクト拒否、解除・再読込・無操作時の破棄を確認しました。確認範囲に実証されたキー漏洩経路はありません。ただし、配布コードの改ざん・端末侵害なども含む「絶対に漏洩しない」保証ではありません。詳しくは [セキュリティ設計](security.md) を参照。

実キーによるGoogleからの生成結果、実モデルの品質・速度、課金・利用枠・通信制限、Safari/Firefox、公開HTTPS環境でのヘッダー・CORSは未検証です。今回の修正とレビューだけで、これらの確認済みや一般公開済みとは扱いません。
