# AI Studio Buildへ渡す開発指示

2026-10-13。以下は未実行の開発指示です。[AI Studio](https://aistudio.google.com/)のBuildで、各段階の動作を確認してから次を渡します。最初から全機能を一括実装するより、編集基盤とAI接続を順に検証する方針です。

モデルと料金の仕様は変わりうるため、Buildにも下記のGoogle公式資料を確認させます。画像生成モデルは `gemini-nano-banana-2.1` に固定し、古いモデルへ無断で置き換えさせません。

## 1. まず編集基盤を作る

```text
日本語UIの個人用ウェブ画像編集アプリ「Nano Banana Editor」を作ってください。
React + TypeScriptとNode.jsサーバーのフルスタック構成にしてください。まずAI APIを呼ばず、ローカル編集機能を実装して動作確認します。

目的は、ブラシで編集したい範囲を選び、AIでその部分を変えられる簡易Photoshopです。今回はAI接続の準備までです。

画面は左にツール、中央に大きいキャンバス、右にレイヤー・参照画像・編集指示、下に履歴を配置してください。落ち着いたダークグレー基調で、主要ボタン「生成」「採用」「保存」が見つけやすいUIにします。

実装する機能：
- PNG/JPEG/WebP読み込み、新規キャンバス、ズーム・パン。
- 選択ブラシ、選択消しゴム、矩形、投げ縄、選択解除・反転。
- マスクは画像画素の座標で管理。ズーム・devicePixelRatioで選択位置がずれないこと。
- 指示用スケッチをマスクと別のレイヤーで管理。表示用の選択色を出力に焼き込まないこと。
- 画像・文字レイヤーの追加、移動、不透明度、表示切替、並べ替え。
- Undo/Redo、PNG/JPEG書き出し。
- IndexedDBへのプロジェクト保存と、JSON＋画像Blobを含むZIPの書き出し・再読込。
- 将来の生成候補・費用・エラー表示領域。ただし未実装ボタンは状態が分かるようにする。

画像はBlobで保存し、大きなbase64をlocalStorageへ保存しないでください。保存に失敗したら保存済みと表示しないでください。画像の元データを上書きせず、編集は新しい状態として保存してください。

原画像O、生成候補G、編集マスクMを受け取り合成する独立した関数を用意してください。M=0の画素はOのRGBAを直接コピーし、M=1ではGを使います。半透明の境界はpremultiplied alphaで扱い、境界ぼかしは選択の内側に限定します。テスト用Gはローカルで作った模様を使い、APIは呼びません。

受け入れ確認：読み込み、ズーム時のブラシ座標、Undo/Redo、レイヤー順、PNG、保存後再読込。マスクがゼロの全画素で元RGBAが一致する自動テスト、半透明の合成、ZIP復元の検証を行ってください。実際に通った確認と未確認の項目を報告してください。
```

## 2. 実モデルの生成・編集を接続する

```text
既存のローカル編集機能を保ちながらNano Banana 2.1を接続してください。
正式モデルIDは gemini-nano-banana-2.1 です。
まず以下の公式仕様を確認してください：
https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1
https://ai.google.dev/gemini-api/docs/image-generation
https://ai.google.dev/gemini-api/docs/interactions-overview
https://ai.google.dev/gemini-api/docs/aistudio-build-mode

新規接続は現行のInteractions APIを基本にし、依存をImageGenerationAdapterにまとめてください。インストールされている公式SDKの対応版を確認し、SDKが未対応なら公式REST仕様を使います。generateContentへ切り替える場合は理由を説明し、正しい画像生成設定と会話のthought signaturesを扱ってください。

APIはNodeサーバーから呼び、AI StudioがSecretに設定するGEMINI_API_KEYを使います。クライアントのコード、VITE変数、localStorage、ログにキーを含めないでください。

最初はテキスト生成と元画像＋文章による編集だけを実装してください。
既定は1K、1候補、medium、検索OFF。生成は利用者がボタンを押した時だけです。画像読込や画面表示で自動生成しないでください。
Interactionsは初期版store=falseで、必要な元画像と短い文脈を明示的に送ります。historyを無制限に毎回送らないでください。system instruction、tools、generation configは要求ごとに明示してください。

最終画像と途中の思考画像を区別してください。複数の出力、画像なし、拒否、usage、検索出典の形式を調べ、結果をアダプターで正規化してください。画像なしを成功にしないでください。

生成結果は候補として比較表示し、「採用」で新規レイヤーへ追加します。送信時のprojectRevision・元画像・マスクを固定し、待機中の変更を古い結果で上書きしないでください。UndoでAPIを再呼び出さず、保存状態を戻します。

画像出力の目安は1K $0.0336/枚です。入力・テキスト・思考・検索は別料金と表示します。料金は定数を一か所に集約し、更新日を記録してください。
二重クリック・SDKの再試行を調べ、不明なタイムアウトを自動で再生成しないでください。429、認証、拒否、ネットワーク失敗を識別し、元画像を保持してください。

まずモック応答で統合を検証し、ビルドと必要なテストを通してください。画像生成の有料呼び出しは自動テストで実行しないでください。接続の準備状態と、ユーザー操作で実施すべき1枚のスモークテスト手順を示してください。
```

## 3. マスク・手描き指示を接続する

```text
局所編集とスケッチ指示を追加してください。前段階の機能を保ってください。

重要な制約：Nano Banana 2.1のマスク編集は能力として公式に紹介されていますが、公開Developer APIに専用mask引数は確認できていません。mask、mask_image等の独自フィールドをAPIへ送らないでください。seedで同じ画像になると約束せず、seed/temperature/topP/topK設定をUIへ追加しないでください。

元画像と、選択・スケッチを視覚的に説明する注釈画像を通常の画像入力で送り、文章で画像の役割を説明します。元画像＋文章だけの方式とも比較できるようにしてください。注釈の色や線を完成画像に残さない指示を追加しますが、モデルだけで消える保証はありません。

生成結果を全面置換せず、送信時に固定した元画像とマスクでローカル合成してください。選択範囲外は元RGBAからコピーし、選択内だけ生成結果を使います。ぼかしは選択の内側です。マスクの表示色・指示線は出力へ焼き込まないでください。

局所編集の合成済み画像を新しい結果バージョンとして保存し、表示・書き出しの正本にしてください。元のレイヤー状態は履歴で保持し、正本の下に再合成しません。通常のsource-overでマスク付き生成レイヤーを上乗せするだけでは、半透明画素の置換になりません。元画像と生成画像がともに半透明で、M=0・0.5・1のケースも確認してください。

原画像とAPI作業画像の変換を記録し、出力の寸法を検査して生成画像だけを逆変換してください。元画像をAI画像に合わせてリサイズしないでください。未知の寸法や大きな構図ずれは自動適用せず、候補として表示してください。元JPEGの圧縮バイトまで保存すると説明せず、アプリ内の正規化RGBAでの保持と説明します。

編集用プリセット：物を消す、衣装を変える、背景を変える、質感を変える、スケッチを仕上げる。各プリセットも普通の文章指示として実装します。
小さなラベル文字はAIだけで正確と約束せず、文字レイヤーで重ねられる導線を用意してください。

マスク外RGBAの一致、ズーム、ぼかし、半透明、API寸法差、生成中のレイヤー変更、注釈線の除外、Undo/Redoを検証してください。APIの有料生成は自動テストで行わず、実画像での品質確認手順を示してください。
```

## 4. 参照・高解像度・検索を追加する

```text
安定した編集基盤に以下のモデル機能を追加してください。仕様は現行Google公式資料で再確認してください。

- 1K/2K/4K、14の比率：1:1,1:4,1:8,2:3,3:2,3:4,4:1,4:3,4:5,5:4,8:1,9:16,16:9,21:9。
- minimal/medium/highの思考設定。minimalを「思考OFF」と呼ばないでください。
- 参照画像の追加と役割指定（人物、商品、雰囲気、構図）。入力画像合計14枚まで、人物最大4・物体最大10という仕様を区別してください。元画像と注釈画像も合計枚数に含めます。
- 候補数1〜4。独立した生成を使う場合、候補数に応じて呼び出し数・費用を表示してサーバーでも上限を検査します。画像枚数を厳密に強制できる未確認パラメーターを作らないでください。
- Web検索・画像検索の切替。既定OFF。Interactionsの現行google_search/search_types設定を確認してください。
- 検索出典とsearch suggestionsを仕様どおり表示します。検索リクエストは複数発生する場合があるため固定額を約束しないでください。実人物の画像検索を利用しないでください。
- キャンバス拡張。元画像領域を保護し、増えた空白だけAI候補から合成します。

画像出力目安：1K $0.0336、2K $0.0504、4K $0.1134。4Kトークンの公式資料に不一致があるため料金表の3780を基準にし、usageと実請求は別扱いにします。API入力や思考等も追加されます。
APIの14画像制限、比率、解像度はクライアントとサーバーの両方で検査し、設定による過大なメモリ確保を防いでください。4Kパノラマは長辺4096を超える場合があります。

キーボード操作・ラベル・フォーカス・比較画面、エラーと保存の挙動を確認し、通った検証を報告してください。公開・共有はまだ行わないでください。
```

## 5. 動画・PDF・Batchの拡張

```text
既存機能を維持し、動画・PDFを参照して画像を作る機能とBatch処理を追加してください。
動画を出力する機能とは説明しないでください。PDFも参照入力で、編集可能PDFを書き出す機能ではありません。
Files APIまたは公式の対応する入力方式・サイズ上限・保存期間を現行資料で確認してください。Cloud固有のファイル上限をDeveloper APIの上限として流用しないでください。

Batchは通常生成とは別の画面にし、項目、概算費用、明示的な実行、ジョブID、状態確認、部分失敗、結果取得、保存を実装してください。低料金を優先して待てる用途向けと説明し、即時完成を約束しないでください。
プロセス再起動後に未完了ジョブを取得できる保存方式を設け、サーバーの一時メモリだけに置かないでください。課金上限の判定はブラウザだけで行わないでください。
自動テストはモックで行い、有料ジョブを勝手に送信しないでください。
公開が必要になった段階で、認証、利用者ごとの回数制限、作成者の予算制御を実装します。今回は個人用非公開プレビューまでにしてください。
```

## 手動の初回確認

有料APIを使えるプロジェクト・利用枠を確認してから、利用者の生成ボタン操作で1K・1候補のテストを行います。まず1枚生成し、次にその画像の一部分を編集します。モデルID、最終画像、usage、エラー、履歴、保存、選択外の差分を確認した後に拡張へ進みます。

UIが表示されること、API呼び出しが成功すること、局所編集の品質がよいこと、保存画像を復元できることは、それぞれ別の確認です。この資料の作成時点ではいずれもアプリでの実行検証はしていません。
