# 公開後の再レビュー（2026-10-13）

本人の初回実生成で404が発生したことを受け、Astra 2担当と主担当で再レビューした。対象は生成API互換性、キー保護と非同期処理、編集・保存・起動・公開配信。実キーの取得や有料生成は行っていない。

## 見つかった問題と修正

| 重要度 | 問題 | 修正 |
|---|---|---|
| P2 | 編集の画像準備中に切断し別キーで再接続すると、旧操作が新キーで送信される | 接続世代番号を開始時に取得。切断で番号を更新し、RPC送信直前と結果受領後に照合する |
| P2 | 画像検索の公式応答の出典と検索語が候補画面に出ない | `sourceUri`を出典URLとして安全検査し、`imageSearchQueries`から画像検索リンクを作成。Web検索との混在・重複・危険URL・snake_caseも検査 |
| P2 | Batchのテキストのみ・空・思考画像のみの応答が失敗件数に加算されない | 最終画像を含まない項目をエラーへ加算し、成功画像は維持する。Google側のジョブ状態と各項目の画像取得成功を区別 |

新しい単体テスト3件とブラウザテスト1件は、修正前に失敗することを確認してから修正した。修正前のChrome再現試験では新しいダミーキーによるPOSTが発生した。修正後は旧操作のPOSTが0件で、新しく押した生成ボタンだけが送信される。

仕様の根拠は[Google Image 定義](https://ai.google.dev/api/generate-content#Image)、[GroundingMetadata 定義](https://ai.google.dev/api/generate-content#GroundingMetadata)、[FinishReason の NO_IMAGE](https://ai.google.dev/api/generate-content#FinishReason)。モデルIDと通常生成・Batchの本文は[公式モデル仕様](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1)、[GenerateContent REST](https://ai.google.dev/api/generate-content)、[Batch REST](https://ai.google.dev/api/batch-api)と独立照合した。

## 維持した保護

- キーは専用Workerの一時メモリ。接続世代番号は数値で秘密情報を含まない。
- 固定Googleオリジンの認証ヘッダー、リダイレクト拒否、credentials omit、文書とWorkerの別CSPを維持。
- React状態・Storage・プロジェクト・URL・Vercelへのキー保存を追加していない。
- 404だけ同モデルのv1beta対応を確認し、同本文で1回だけ生成する限定再試行を維持。401/403/429/5xxは再送しない。
- 検索HTMLのsandbox、生エラー非公開、成功応答のキー伏字化、プロジェクトallowlist、画像実寸・レイヤー画素制限を維持。
- 修正差分をAstraが独立再確認。追加の重大な問題は指摘されていない。

## 実APIと自動テストの区別

本人の公開アプリで新規生成・1K・検索オフの赤いリンゴが生成できたことは、成功報告と候補画像で確認済み。案内は採用・PNG書き出し・切断まで含むが、各操作を個別に観察したとは扱わない。

今回の自動Google通信は、すべて隔離Chromeでのダミーキーとモック応答。公式仕様への適合とアプリの処理を検査するもので、利用者ごとの権限・課金・利用枠やGoogleの実出力品質は検査していない。実APIの部分編集・スケッチ・検索・Batchは未確認。切断は、すでにGoogleへ送った操作やBatchジョブの削除・請求取消を意味しない。
